# auth-session Specification

## Purpose
Сессия позволяет приложению показывать состояние вошедшего пользователя, восстанавливать доступ после обновления страницы и выполнять выход.

## Requirements

### Requirement: Состояние вошедшего пользователя
После успешного входа или регистрации приложение SHALL сохранять полученный токен доступа и идентификатор пользователя. Каталог SHALL показывать доступные данные профиля и кнопку «Выйти» вместо ссылок на вход и регистрацию.

#### Scenario: Успешная авторизация
- **WHEN** API возвращает токен доступа и идентификатор пользователя
- **THEN** приложение загружает профиль и показывает в каталоге данные пользователя и кнопку «Выйти».

### Requirement: Восстановление и обновление доступа
Приложение SHALL сохранять accessToken и идентификатор пользователя после входа. При запуске с действительным accessToken приложение SHALL использовать его для загрузки профиля без вызова `/auth/refresh`. Приложение SHALL вызывать `/auth/refresh` только после истечения accessToken. Одновременные запросы SHALL использовать один общий вызов refresh. После успешного refresh приложение SHALL сохранить новый accessToken; браузер обновляет refresh-cookie из ответа API. Исходный запрос SHALL повторяться с новым токеном не более одного раза. При неуспешном refresh приложение SHALL завершать локальную сессию.

#### Scenario: Обновление страницы с действующей сессией
- **WHEN** пользователь обновляет страницу до истечения accessToken
- **THEN** приложение загружает профиль с сохранённым токеном и не вызывает refresh.

#### Scenario: Истёкший токен при запросе
- **WHEN** accessToken истёк и обновление токена успешно
- **THEN** приложение вызывает refresh один раз и выполняет запрос с новым токеном.

#### Scenario: Одновременные запросы после истечения токена
- **WHEN** несколько запросов обнаруживают истёкший accessToken одновременно
- **THEN** приложение выполняет один refresh и отправляет запросы с полученным токеном.

#### Scenario: Неуспешное обновление
- **WHEN** refresh завершается ошибкой или возвращает непригодный токен
- **THEN** приложение очищает локальную сессию и не повторяет исходный запрос бесконечно.

### Requirement: Выход из аккаунта
При выходе приложение SHALL отправлять запрос на завершение сессии в API при наличии токена, очищать локально сохранённые данные сессии и возвращать каталог в состояние гостя. Локальные данные SHALL очищаться даже при ошибке запроса на выход.

#### Scenario: Нажатие «Выйти»
- **WHEN** вошедший пользователь нажимает «Выйти»
- **THEN** после попытки завершить сессию каталог показывает ссылки на вход и регистрацию вместо профиля.
