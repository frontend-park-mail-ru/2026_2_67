# auth-session Specification

## Purpose
Сессия позволяет приложению показывать состояние вошедшего пользователя, восстанавливать доступ после обновления страницы и выполнять выход.

## Requirements

### Requirement: Состояние вошедшего пользователя
После успешного входа или регистрации приложение SHALL сохранять полученный токен доступа и идентификатор пользователя. Каталог SHALL показывать доступные данные профиля и кнопку «Выйти» вместо ссылок на вход и регистрацию.

#### Scenario: Успешная авторизация
- **WHEN** API возвращает токен доступа и идентификатор пользователя
- **THEN** приложение загружает профиль и показывает в каталоге данные пользователя и кнопку «Выйти».

### Requirement: Восстановление и обновление доступа
При запуске с сохранённым идентификатором пользователя приложение SHALL пытаться обновить токен через API и загрузить профиль. При ответе 401 на авторизованный запрос приложение SHALL пытаться обновить токен и повторить запрос после успешного обновления.

#### Scenario: Обновление страницы с действующей сессией
- **WHEN** пользователь обновляет страницу и API успешно обновляет токен
- **THEN** каталог показывает авторизованное состояние без повторного ввода учётных данных.

#### Scenario: Истёкший токен при запросе
- **WHEN** авторизованный запрос получает ответ 401 и обновление токена успешно
- **THEN** приложение повторяет запрос с новым токеном.

### Requirement: Выход из аккаунта
При выходе приложение SHALL отправлять запрос на завершение сессии в API при наличии токена, очищать локально сохранённые данные сессии и возвращать каталог в состояние гостя. Локальные данные SHALL очищаться даже при ошибке запроса на выход.

#### Scenario: Нажатие «Выйти»
- **WHEN** вошедший пользователь нажимает «Выйти»
- **THEN** после попытки завершить сессию каталог показывает ссылки на вход и регистрацию вместо профиля.
